Quick Guide

Two lightweight tools built around a stack of sliced scan images — no server, no login, just files.

Educator annotates in Annotator → Exports annotations.json → Student opens Quiz

E For educators — Annotator

annotator/index.html

  1. Scrub through the slices Use the slider (or Play) below the image to move through the stack.
  2. Add an annotation Drag a type from the left palette onto the spot on the slice — or on touch, tap the type, then tap the slice. Fill in its content in the panel on the right.
  3. Set its acceptable zone A radius slider is the quick default; "Draw shape" lets you trace a custom region instead — this is how close a student's guess needs to be to count as correct.
  4. Span several slices if the feature does In the "Slices" section set a from/to range and the annotation appears on every slice in it, sharing one zone. An organ rarely looks the same on every slice, so under "Zone per slice" pick Slice N only and move, resize or redraw the zone for that slice alone — a badge on the image reminds you which you're editing. The strip of slice chips shows which slices have their own zone (dot) and jumps between them; Copy from seeds a slice from a neighbour, Use on all slices makes a slice's zone the shared one, Reset to shared drops it.
  5. Browse and fix things up "On this slice" and the expandable "All annotations" list (sortable) jump you straight to any item. Drag a marker to reposition it.
  6. Export Choose Quiz (students place things themselves) or Showcase (read-only walkthrough) — and for a quiz, Full challenge (slice hints only after a miss) or Guided (slices hinted from the start). Downloads annotations.json, stamped with a fingerprint of the image stack so the quiz can warn if the images change.

Annotation types

  • Text label — short text shown right on the image
  • Pin + description — marker with a longer write-up
  • MCQ — marker with a multiple-choice question
Work autosaves to the browser as you go, in a slot tied to this image stack; a banner warns if the browser is blocking storage. Import… loads a previous export back in for further editing, and asks first if the file was made for a different image stack.

S For students — Quiz

quiz/index.html

If it's a Showcase: click any item in the list — it jumps to the right slice and shows its full content. Nothing to do but read.

If it's a Quiz: you work through the items one at a time.

  1. Start The panel on the right tells you how many items there are. Press Start (or Continue, if you've been here before — progress is saved in this browser).
  2. Place the current item Scrub through the slices, then tap the spot where you think the feature belongs. Drag your marker to adjust it, then press Check placement. In guided quizzes a highlight under the slider shows which slices to look at.
  3. Answer MCQs in place Questions are already sitting at their true spot (the ? marker). Pick an answer and press Check answer.
  4. Miss? You get help The feedback says whether it was the wrong slice or the wrong spot. After one miss you're told which slices to look at; after two, the accepted zone is outlined; after three, Show me reveals it (counted as shown, not solved).
  5. Skip and come back Skip moves on; any item in the Progress list can be reopened. Summary shows how you did and lets you retry any item; Start over wipes everything.

Status icons (progress list)

  • Not started
  • Attempted, not yet checked
  • Skipped
  • Correct
  • Shown (used "Show me")
Import… loads a different annotations.json if you have one — otherwise the quiz uses whatever file is bundled next to the page.

Using your own images

Swap out the sample apple-slice dataset for a real one

Drop .svg, .png, .jpg/.jpeg, .gif or .webp images into data/slices/ (names can have spaces), then run python3 scripts/build_manifest.py to rebuild the slice list — files sort naturally by name, so abc2.jpg comes before abc10.jpg whether or not you zero-pad. The script also records a fingerprint of the stack, which exports carry, so both tools can warn when an annotations file doesn't match the images. Changing, adding or renaming a slice shifts the numbering, so re-export after any change to the images. See the README for the full technical reference, including the annotations.json schema.

Pure HTML/CSS/JS, no server-side storage — everything here is just files in this folder.
